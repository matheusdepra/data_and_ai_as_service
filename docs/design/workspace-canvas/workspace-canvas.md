# Workspace Canvas Specification

Version: 1.0

Status: Draft

---

# Purpose

Workspace Canvas is a visual representation of the current Workspace.

It allows users to understand:

* Which datasets are being used
* How datasets are connected
* Which relationships were selected
* Which outputs are being generated
* How Dativerso is reasoning about the solution

The Canvas is not a separate workflow.

The Canvas is a visual view of the current Workspace.

---

# Position in Product

```text
Workspace
├── Chat View (Default)
└── Canvas View
```

Users can switch between both views at any time.

Both views represent the same workspace state.

---

# Core UX Principle

The Canvas should explain.

Not configure.

The user should never be required to manually build relationships, drag datasets or design pipelines.

Dativerso proposes.

Users review and approve.

---

# Primary Objectives

The Canvas should answer:

```text
What datasets are involved?

How are they connected?

Why were they selected?

What is being generated?

Can I trust this output?
```

# Canvas Visualization

## Purpose

Provide a visual explanation of the workspace.

---

# Dataset Nodes

Each dataset appears as a node.

Display:

```text
Dataset Name

Rows

Columns

Confidence

Primary Key
```

---

## Example

```text
Customer Dataset

12,340 Rows

42 Columns

94% Confidence

customer_id
```

---

# Relationship Links

Display connections between datasets.

Example:

```text
Customer Dataset
     │ customer_id
     │
Orders Dataset
```

---

## Relationship Confidence

Show confidence level.

### High

```text
80% - 100%
```

Color:

```text
Green
```

---

### Medium

```text
50% - 79%
```

Color:

```text
Orange
```

---

### Low

```text
0% - 49%
```

Color:

```text
Red
```

---

# Suggested Relationships

Not yet approved relationships appear as dashed lines.

Purpose:

Allow users to understand possible connections before approval.

---

---

# Auto Layout

Default:

```text
Enabled
```

The platform automatically organizes the canvas.

Users should not manually position nodes.

---

# Canvas Controls

Keep controls minimal.

Allowed:

```text
Fit to Screen

Focus Mode

Show Confidence

Show Metrics
```

---

Avoid:

```text
Manual Layout

Custom Connectors

Free Drawing

Pipeline Editing
```

This is not a modeling tool.

# Generation Flow

Dativerso should never create outputs immediately.

Flow:

```text
User Request
↓
AI Reasoning
↓
Canvas Update
↓
Preview
↓
Approval
↓
Generate Output
```

---

# Explainability Requirement

Every generated output must provide:

```text

Relationships used
```

# Empty State

If no relationships exist yet:

Message:

```text
Describe what you want to build and Dativerso will create a visual plan.
```

Action:

```text
Open Workspace Chat
```

---

# Explicitly Avoid

Do not expose:

```text
SQL

dbt Models

Cloud Run Jobs

BigQuery Tables

Bronze Layer

Silver Layer

Physical Storage
```

These concepts belong to implementation and infrastructure.

---

# Success Criteria

Users should be able to:

1. Understand how datasets are connected
2. Understand why outputs were proposed
3. Validate relationships before creation
4. Trust AI recommendations
5. Approve outputs with confidence

The Canvas should feel like a visual explanation of Dativerso's reasoning, not a traditional ETL designer or data modeling tool.
